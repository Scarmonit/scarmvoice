A pass over the things that only go wrong occasionally

**An update that fails to install no longer takes the app with it**

Updates are applied at startup, before the app exists: the window, the tray and
your session are all held back so the new version can replace the old one
cleanly. If that handover failed — an antivirus tool holding the downloaded
installer, an installer that never started — the app was left running with no
window and no tray, and no way to reach it. Launching it again did nothing,
because the copy already running answered and turned the request away. Ending
the task was the only way out.

Now the handover is given a deadline. If the installer does not take over, the
app starts normally instead, with the update still on disk and still applied the
next time you close it.

**It keeps looking for newer versions while one is waiting**

An update that had downloaded and was waiting on the pill stopped the app ever
checking again. Leave the app in the tray for a few days and the first update it
found was the last one it would hear about — including a release that fixed
something in the one it was holding.

The pill also stopped claiming a download had failed when nothing had been
attempted: a failure from an earlier version was being shown over a new one.

**"Someone is typing…" that never stopped**

If the connection dropped and came back while somebody was typing, their name
could stay in the typing line for the rest of the session. Nothing could clear
it — not them stopping, not them sending the message — except leaving the
channel and coming back. It clears itself now, the same way it always did when
the connection was healthy.

**An unsent thread reply can no longer end up in the wrong place**

Text left in a thread's reply box is kept and handed back when you return to
that thread. It was being remembered by the thread's number alone — and a
channel thread and a conversation thread can carry the same number. So a reply
written in a channel could reappear, already typed, in the reply box of a
private conversation, one Enter away from being sent to the wrong person.
Drafts are now tied to the conversation as well as the thread.

Relatedly, a reply that fails to send now goes back to the thread it was written
for. If you had moved to a different thread while it was sending, it used to
land in whichever box was in front of you.

**Saving and copying larger images**

Saving or copying an image from a link stopped after twenty seconds, whether or
not it was still transferring — so anything past a few megabytes could not be
saved at all on a normal connection. The twenty seconds now covers reaching the
site, not the download behind it.

Large files also read correctly: an attachment near the one-gigabyte limit
showed as "1024.0 MB" instead of "1.0 GB".

**The appearance preview in Settings is a picture again**

The sample messages under Settings → Accessibility are drawn by the real message
list, which meant they carried real actions on messages that do not exist.
Clicking a reaction on the preview produced an error, and right-clicking one and
choosing Reply attached a phantom quote to the next real message you sent. The
preview no longer responds to clicks.

**Under the hood**

- The app now only uploads files you actually chose in a dialog or dropped on
  the window. Nothing else on your machine can be sent, whatever asks.
- An image dragged in from another window is held to a sensible size limit, so
  an enormous one cannot exhaust the app's memory.
- When the noise filter fails to start, the audio device is released instead of
  being held open for the rest of the session.
- A message you have just posted no longer goes briefly missing if the
  connection stumbles while the list is refreshing.
