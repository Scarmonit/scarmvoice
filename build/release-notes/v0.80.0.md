Your window where you left it, and messages that appear when you press Enter

**Your window size and position survive a restart of your computer**

Quitting and reopening the app always brought the window back where you left
it — but restarting the computer reset it to the size and place it had on the
day it was installed. The cause was the copy of the app that starts hidden in
the tray when you log in: it builds its window in the first seconds of your
session, exactly when Windows is still waking monitors and settling display
scaling, and anything that nudged that invisible window was being saved over
the geometry you had actually chosen.

The app no longer records the position of a window you have never seen. And the
first time you open the window each session, it re-checks your saved size and
position against the screens that exist right then — so even a launch that
happened while the displays were half-awake comes up where you put it.

**Settings can no longer quietly reset themselves**

If the settings file on disk could not be read — a power cut mid-write, a disk
busy with everything else a login starts — the app used to shrug and start
fresh, as if it had just been installed. Every save now keeps the previous good
copy of your settings alongside the new one, and if the main file ever reads
back broken, the app restores from that copy instead of resetting.

For the curious: your settings live in the app's own data folder under
AppData\Roaming, not in a temporary folder — a cleanup tool that empties temp
and cache locations does not touch them.

**Sending a message feels instant**

A message used to appear only after the server had confirmed it — a round trip
that sat between pressing Enter and seeing your own words, long enough to make
every send feel sluggish. Your message now appears in the conversation the
moment you press Enter, in channels and in private conversations alike, and the
confirmation catches up behind it.

Nothing about delivery has changed. If the send fails, the message comes back
down and is queued to retry — or handed back to the box — exactly as before.
