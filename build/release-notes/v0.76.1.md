Four fixes, and Edit Layout doing what it said it would

**The cursor fell behind what you were typing in a code block**

Inside a ``` block the message box drew your text in a different typeface from
the one the cursor was moving through, so the two came apart a little more with
every character — the words ran out ahead and the caret sat somewhere back near
the start. Bold and italic had the same fault, more slowly.

The box paints one typeface now, always, and shows formatting with weight,
colour and background instead of by changing the letters themselves. Bold still
looks bold, code still sits on its own tinted plate, and the cursor stays where
the next character is going to appear.

One thing genuinely changed: italics are no longer slanted in the box while you
write them. Slanting reshapes the letters, and reshaping them is exactly what
moved the cursor away from the text. The `*` marks around the word still dim,
and the message itself is italic when it arrives.

**The Format button had no hover state at all**

It was drawn beside the emoji and microphone buttons but had inherited none of
their styling, so the pointer never changed over it and nothing lit up. It looks
and behaves like the buttons either side of it now, and stays lit while the
toolbar is open. The whole cluster is styled as a group, so the next button
added there cannot arrive half-dressed.

**Screen share now offers everything**

Every window on the machine, ScarmVoice's own included. It used to hide anything
called ScarmVoice — showing somebody a message you have just received is an
ordinary thing to want, and the app refusing to be shared is not a decision it
should have been making for you.

- **Every open window, one by one** — each browser window separately, editors,
  terminals, whatever is running.
- **A search box**, because the list is now as long as your desktop is busy. It
  says how many windows there are and how many match.
- **Sorted**: screens first, then windows by name, with anything Windows would
  not give a preview for at the end rather than scattered through the middle.

**Edit Layout: every section, into any zone**

The first version could only do a few of the things it appeared to offer. The me
bar looked movable and then refused every target, and the message box could not
be moved at all. The reason was the same for both: it was built as three
either-or switches rather than as a set of places, so most of the places you
could drag something to did not exist.

It is a grid of zones now. There are seven — a bar across the top, the left
column, the right column, the bottom-left corner, a bar across the bottom, and
above or below the messages in the chat column — and any section can go in any
of them. Drop one onto a zone that is already taken and the two swap.

- **Every zone is drawn while you edit**, including the empty ones. That is what
  was actually missing: a zone with nothing in it had no size, and something
  with no size cannot be dropped on.
- **Picking a section up shows you all seven**, each one labelled, and says what
  it would swap with.
- **The drop happens where you let go**, not wherever the pointer last passed
  over on the way there.
- **Your saved arrangement and your templates carry over** — the old three-switch
  form is translated, not discarded.
- **Cancel and Escape** still put back what you started with, and **Reset**
  returns to the normal window.

**Also**

- The message box goes back to the zone you chose after a conversation closes.
  It used to return to wherever it had been the first time you ever opened a
  conversation, which would have undone your arrangement every time.
- A panel's drag-to-resize strip now appears only when it is in a column, where
  there is a width to drag, and moves to whichever edge faces the chat.
- Twelve more tests, including one that fails if any part of the message box's
  formatting is ever set in a way that could move the cursor away from the text
  again.
