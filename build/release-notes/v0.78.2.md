Arrow keys and Tab inside a code block

**The arrows were dropping the caret into the title bar**

The opening ``` line is drawn as the block's title bar and the closing one as
its bottom edge — both with their own text made invisible. Nothing told the
arrow keys that. So pressing Up from the first line of code put the cursor
*inside the title bar*: a place with nothing to see, where anything typed
quietly breaks the fence. That is what it looked like when the caret "escaped
the block".

The arrows step over both of them now:

- **Up from the first line of code** goes to the line above the block, past the
  title bar.
- **Down from the last line** goes to the line below it, past the bottom edge.
- **Between lines of code** nothing is intercepted at all — the cursor already
  moves correctly there, and which column it remembers is the text box's own
  business.
- **A click on the title bar or the bottom edge** puts the cursor in the code
  rather than leaving it somewhere invisible.

Walking down through a message from top to bottom now never rests on a fence
line, and leaving the block still happens the moment you arrow past its first or
last line — on purpose, which was always the intention.

**Tab indents instead of walking away**

Inside a code block, **Tab** indents and **Shift+Tab** outdents:

- With nothing selected, Tab inserts an indent where the cursor is.
- With lines selected, Tab indents every line the selection touches, and the
  same text stays selected — so you can press it twice.
- Shift+Tab takes one indent's worth of space back off, and stops at the margin
  rather than eating into the code.

**Outside a code block Tab is unchanged.** It still moves to the next control,
because that is how somebody who does not use a mouse reaches the send button.

**Also**

- A code line long enough to wrap is left to the text box, which knows which
  visual row the cursor is on when this does not. Anything that comes of that is
  caught afterwards, so the cursor still never ends up on a fence line.
- The message is still an ordinary Markdown fenced block. Indenting writes
  spaces into the code, which is what indenting is.
