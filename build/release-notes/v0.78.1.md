The code block in the message box, finished properly

**It looked unfinished, and it was**

A code block in the message box was a flat black slab with no edges, a small
language pill floating in one corner of it, and a red spellcheck squiggle
running through the code. It read as something half-drawn rather than as a code
editor.

**Now it is a panel**

- **A bordered, rounded panel** that is clearly its own thing, inset from the
  message box around it, so a code block stops bleeding into the message.
- **A title bar across the top of it** with the language on the left and the
  block's own **…** on the right — a proper control, the full width of the
  panel, rather than a pill in the corner. Clicking the language changes it;
  the **…** offers *Change language*, *Copy code* and *Remove code block*.
- **Numbered lines** in a gutter that is inside the panel, where they belong.
- **Syntax highlighting** in the language the block is tagged with.
- **No spellcheck.** Code is not prose and does not get red squiggles.
- **The backticks stay out of sight.** The opening line is the title bar and the
  closing one is the panel's bottom edge — they are still in the message and
  still what gets sent, you just stop having to look at them.

**A note on the spellcheck**

A message box is one field and it spell-checks all of itself or none of itself.
So while a message holds a code block, spellcheck stops for the whole box — the
same trade the code face already makes. Red squiggles under every identifier are
worse than none under the sentence above them, and the moment the block goes,
spellcheck comes back.

**Also**

- The panel is DRAWN rather than laid out — a border, rounded corners and a
  gutter are all things the text would otherwise have to move for, and nothing
  in this layer is allowed to move the text, because the cursor is what would
  stop pointing at it.
- The message is still Markdown: a fence, a language tag and the code between
  them. Nothing about what gets stored or sent has changed.
